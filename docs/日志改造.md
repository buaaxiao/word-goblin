# 日志改造

## 一、为什么要改

改造前的日志问题：

- 业务代码大量直接调用 `console.log / console.warn / console.error`，分散在各文件，**没有统一的标签、级别和出口**。
- 日志只在浏览器 DevTools 可见：**无法导出**、**无法带出页面排查问题**、**多会话之间不留存**。
- 没有级别控制：全量输出 vs 全量关闭，二选一；线上问题定位只能靠肉眼翻控制台。
- 没有持久化：刷新即丢，问题复现时现场已被清空。

## 二、改造目标

1. 统一日志出口：所有业务日志走 `Log.*` 体系（带模块标签），`console.*` 全部替换。
2. 可配置级别：`DEBUG / INFO / WARN / ERROR / SILENT`（外加 TRACE），低于级别的日志不写文件。
3. 可配置保留/导出行数：内存缓冲、IndexedDB 落盘、导出 `.log` 文件统一按该上限裁剪，最大 **3000 行**（0 表示不保留）。
4. 持久化：日志级别与可导出行数作为设置项，持久化到 **IndexedDB**（settings 仓库）+ localStorage 兜底。
5. 可导出、可清空：一键导出 `.log` 文件，一键清空，服务排查。

## 三、总体架构

```
console.*（已全部替换为 Log.*）
        └─► loglevel 命名 logger（受级别过滤，未达级别不打印不记录）
              └─► 自定义 methodFactory ──► 内存缓冲（上限 N）
                                              └─► 批量落盘 IndexedDB logs 仓库（上限 N，自动裁剪最旧）
                                                    └─► 导出 .log 文件（最多 N 行）
```

- `lib/loglevel.min.js`：v1.9.2，提供日志级别控制与命名 logger。
- `js/logger.js`：负责「级别接入 + 内存缓冲 + 落盘 IndexedDB + 导出 + 清空 + 全局错误兜底」。
- `js/db.js`：`logs` 对象仓库（`seq` 自增主键 + `ts` 索引），提供 `dbPutLogs / dbGetAllLogs / dbCountLogs / dbClearLogs / dbPruneLogs`。
- `js/constants.js` + `js/config.js`：日志设置项（级别 / 可导出行数）作为普通配置键管理，统一持久化。

## 四、日志客户端 API（js/logger.js）

```js
// 带模块标签（推荐写法，tag 即模块名）
Log.info("storage", "保存完成", diff);
Log.debug / Log.warn / Log.error   // 同上

// 命名 logger
const log = Log.getLogger("dict");
log.warn("…");

// 级别切换 / 读取
Log.setLevel("warn");
Log.getLevelName();   // 当前级别名（小写，如 "info"）

// 落盘 / 统计 / 导出 / 清空
await Log.flush();
await Log.count();        // 已落盘条数（DB 不可用时回退内存数）
await Log.export();       // 导出 .log 文件，返回行数
await Log.clear();        // 清空内存与落盘日志
```

级别过滤语义：

- 命名 logger：低于当前级别的调用既不打印也不记录（loglevel 原生语义）。
- 全局错误兜底：`window.onerror` / `unhandledrejection` 始终以 ERROR 级记录，不丢现场。

## 五、设置项与持久化

沿用通用配置体系（`constants.js` 中 `KEYS` 唯一定义源，`config.js` 负责读写）：

| 设置键 | 存储键 | 说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- | --- |
| `KEY_LOG_LEVEL` | `wordDictation.logLevel.v1` | 日志级别（loglevel 小写值） | `info` | trace / debug / info / warn / error / silent |
| `KEY_LOG_MAX_LINES` | `wordDictation.logMaxLines.v1` | 内存缓冲、落盘、导出统一上限 | `300` | 0 ~ 3000 整数 |

持久化链路（与其它设置一致）：

```
设置界面 → setConfig(KEY_*, value)
        → applyConfigValue（归一化：级别只接受合法小写值；行数钳制到 0~3000）
        → persistConfigKey
             ├─ 异步写 IndexedDB settings 仓库（dbPutSetting）
             └─ 同步写 localStorage（兜底，超配额时降级并告警）
```

启动恢复（main.js）：

```
initApp → loadConfigFromStorage()       // 从 IndexedDB / localStorage 恢复到 config
        → applyLogConfig()              // ★ 应用级别到 loglevel 运行时；按行数收敛内存
```

`applyLogConfig()` 额外做一次**旧键迁移**：老版本 loglevel 直接写 localStorage 键 `loglevel`，首次启动时若发现 `config.logLevel` 仍为默认 `info` 且存在该旧键，则接管其值并写入设置体系（之后统一由配置体系管理，loglevel 不再自持久化）。

## 六、console → Log 全量替换

一次性把业务代码中的 `console.*` 替换为 `Log.*`（共 **97 处、15 个文件**），替换规则：

| 原调用 | 替换为 | 标签来源 |
| --- | --- | --- |
| `console.log(...)` | `Log.info(...)` | 消息开头的 `[模块] ` 前缀 |
| `console.info(...)` | `Log.info(...)` | 同上 |
| `console.debug(...)` | `Log.debug(...)` | 同上 |
| `console.warn(...)` | `Log.warn(...)` | 同上 |
| `console.error(...)` | `Log.error(...)` | 同上 |

- 标签优先取消息开头的 `[模块]`，例如 `"[storage] 迁移完成…"` → `Log.info("storage", "迁移完成…")`；无前缀的（如 `"renderChart 失败"`）按文件归属使用默认标签（`stats` / `help` / `settings` / `dict` 等）。
- 未替换：`js/logger.js` 内部的 console 拦截机制本身、`lib/loglevel.min.js`（第三方）、`data/migrate-ids.js`（独立 Node 脚本）。
- 替换范围：storage / chapters / chapters-modals / words / io / reports / config / settings-store / db / dictation / main 及 4 个 partials 弹窗。

> 行为变化说明：默认 `INFO` 级别下，`DEBUG` 消息不再打印到浏览器控制台（符合级别语义）；需要完整调试信息时，在 设置 → 系统设置 → 日志级别 调低到 DEBUG 即可。

## 七、设置界面

设置 → 系统设置：

- **日志级别**下拉：TRACE 最详细 / DEBUG 调试 / INFO 信息（默认）/ WARN 警告 / ERROR 错误 / SILENT 不记录。切换即持久化并立即生效。
- **可导出日志行数**数字输入：0 ~ 3000（步进 100，0 表示不保留运行日志）。改动后立即按新上限裁剪内存与落盘日志，并持久化。
- **运行日志**：显示「已记录 N 条 · 当前级别 X · 最多保留 M 行」；`导出日志文件` 生成 `.log`；`清空日志` 带确认框。

导出 `.log` 文件头：

```
# 单词精灵运行日志
# 导出时间: …
# 日志级别: INFO
# 导出行数上限: 3000
# 条目数: …
# 格式: 时间 [级别] 内容（异常堆栈跟随其后）
```

## 九、常见问题

- **日志导出行能到多少？** 可配置 0 ~ 3000，上限 3000。超过 3000 的输入会被钳制；配置为 0 时不保留运行日志（内存与落盘均不写入）。
- **为什么 DEBUG 日志不落盘了？** 当前级别为 INFO；调低到 DEBUG 或 TRACE 即可记录更详细日志。
- **清缓存会不会丢日志设置？** 设置持久化在 IndexedDB，localStorage 仅作兜底；导出设置文件可用来恢复。
- **旧版本设置的日志级别还在吗？** 会：首次启动自动从 localStorage 旧键 `loglevel` 迁移到设置体系。
